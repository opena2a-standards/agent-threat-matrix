# T-6001: Memory Injection

**Tactic:** persistence
**Attack Class:** MEM-POISON

## Description

Inject malicious entries into agent memory to persist instructions across sessions

## Procedure Examples

- **DVAA Validation:** L2-04

## Detection

- **HMA Checks:** MEM-001, MEM-002, MEM-003, MEM-004, MEM-005, MEM-006
- **OASB Controls:** 8.1, 8.2, 8.3, 8.4
- **Data Sources:** Agent memory file (hackmyagent check MEM-001); Configuration file (hackmyagent check MEM-002, hackmyagent check MEM-003); Multi-agent configuration (hackmyagent check MEM-004); Application source code (hackmyagent check MEM-005, hackmyagent check MEM-006)

## Mitigation

Apply the [OASB-1](https://oasb.ai) controls that matrix.json maps to this technique:

- OASB 8.1: Conversation Integrity
- OASB 8.2: Context Injection Protection
- OASB 8.3: Memory Isolation
- OASB 8.4: Summarization Security

## Evidence

- **Evidence Tier:** validated
- **Honeypot Telemetry:** AgentPwn contributes live canary-fire evidence for this technique to the Attack Prevalence Index. Those counts measure engagement with the trap, not confirmed agent behaviour: no fire in the corpus has ever been classified as an agent, and crawler traffic is counted rather than filtered.
