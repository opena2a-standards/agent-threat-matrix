# T-3001: System Prompt Credential Extraction

**Tactic:** credential-harvest
**Attack Class:** RETROACTIVE-PRIV

## Description

Extract credentials hardcoded or referenced in the agent's system prompt

## Procedure Examples

- **DVAA Validation:** L1-02

## Detection

- **HMA Checks:** CRED-001, CRED-002, CRED-003, CRED-004
- **OASB Controls:** 5.1, 5.2, 5.3, 5.4, 5.5
- **Data Sources:** Configuration file (hackmyagent check CRED-001, hackmyagent check CRED-004); Environment file (hackmyagent check CRED-001); MCP server configuration (hackmyagent check CRED-001); Agent instruction file (hackmyagent check CRED-001); Private key file (hackmyagent check CRED-002); Package manifest (hackmyagent check CRED-003)

## Mitigation

Apply the [OASB-1](https://oasb.ai) controls that matrix.json maps to this technique:

- OASB 5.1: No Hardcoded Credentials
- OASB 5.2: Context Window Isolation
- OASB 5.3: Credential Scope Limitation
- OASB 5.4: Credential Rotation
- OASB 5.5: Secrets Not Logged

## Evidence

- **Evidence Tier:** observed
- **Honeypot Telemetry:** AgentPwn contributes live canary-fire evidence for this technique to the Attack Prevalence Index. Those counts measure engagement with the trap, not confirmed agent behaviour: no fire in the corpus has ever been classified as an agent, and crawler traffic is counted rather than filtered. They did not affect the tier above. See [Honeypot-Derived Evidence](../EVIDENCE_AUDIT.md#honeypot-derived-evidence-what-it-proves-and-what-it-does-not).
- **Count Caveat:** A minority of this technique's rows come from hand-slugged canaries that resolve to a category but no tier. Each such fire is written once per technique the category maps to, so for this technique the row count exceeds the fire count. Do not read rows as fires.
