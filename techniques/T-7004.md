# T-7004: Memory Dump

**Tactic:** collection
**Attack Class:** MEM-POISON

## Description

Dump the agent's memory store to extract stored data, credentials, and conversation history

## Procedure Examples

- **DVAA Validation:** MemoryBot memory dump

## Detection

- **HMA Checks:** MEM-001, MEM-002, MEM-003, MEM-004, MEM-005
- **OASB Controls:** 4.1, 4.2, 4.3, 4.4
- **Data Sources:** Agent memory file (hackmyagent check MEM-001); Configuration file (hackmyagent check MEM-002, hackmyagent check MEM-003); Multi-agent configuration (hackmyagent check MEM-004); Application source code (hackmyagent check MEM-005)

## Mitigation

Apply the [OASB-1](https://oasb.ai) controls that matrix.json maps to this technique:

- OASB 4.1: Output Validation
- OASB 4.2: Action Confirmation for Destructive Operations
- OASB 4.3: Data Exfiltration Prevention
- OASB 4.4: Output Attribution

## Evidence

- **Evidence Tier:** validated
- **Honeypot Telemetry:** AgentPwn contributes live canary-fire evidence for this technique to the Attack Prevalence Index. Those counts measure engagement with the trap, not confirmed agent behaviour: no fire in the corpus has ever been classified as an agent, and crawler traffic is counted rather than filtered. They did not affect the tier above. See [Honeypot-Derived Evidence](../EVIDENCE_AUDIT.md#honeypot-derived-evidence-what-it-proves-and-what-it-does-not).
- **Count Caveat:** A minority of this technique's rows come from hand-slugged canaries that resolve to a category but no tier. Each such fire is written once per technique the category maps to, so for this technique the row count exceeds the fire count. Do not read rows as fires.
