# Cross-framework mapping

## Cross-Framework Mapping

This matrix maps every technique to four external references:

| Framework | What It Provides |
|-----------|-----------------|
| [HackMyAgent](https://github.com/opena2a-org/hackmyagent) | Automated detection (318 static checks, 164 attack payloads) |
| [DVAA](https://github.com/opena2a-org/damn-vulnerable-ai-agent) | Lab validation (21 agents: 16 deliberately vulnerable, 1 hardened reference, 4 control-protected variants; 12 vulnerability categories) |
| [OASB](https://oasb.ai) | Defensive controls (46 controls across 10 domains) |
| MITRE ATT&CK / ATLAS / OWASP LLM | An index of which techniques this repository's mapping documents name against each framework, and which they do not |

See [cross-references/](../cross-references/) for detailed mapping documents. The DVAA figures are pinned in [`related-projects.json`](../related-projects.json) with the DVAA release they were read from. On each line naming DVAA in README.md and in the pages that took its reference text (`PAGES` in the script, this page among them), `python3 scripts/check_readme_claims.py` reads the wordings "N agents", "N deliberately vulnerable", "N hardened reference", "N control-protected variant(s)", "N vulnerable agent(s)" and "N categories" (up to two words, each a run of ASCII letters and hyphens, may stand between the number and "categories"), in any letter case with one space between words, and fails when one states a different number. A DVAA figure worded any other way is not checked. A line naming DVAA fails the check when it carries a format character (Unicode category Cf, such as a soft hyphen or a zero width space), a control character other than a tab, a Hangul filler, a combining mark that Unicode lists as default ignorable, such as a variation selector, or a code point that Unicode lists as default ignorable without assigning it, because such a character can keep a figure from being read while the line still shows it. A line names DVAA when it contains "DVAA" once such characters are removed, either as it then stands or after three more steps, with no combining mark (Unicode category M) directly after it that NFKC joins to the last A. So "DVAA" followed by U+0301 COMBINING ACUTE ACCENT, which NFKC joins to the A as U+00C1 LATIN CAPITAL LETTER A WITH ACUTE, does not name DVAA, nor does "DVAA" followed by U+0332 COMBINING LOW LINE and U+0301, while "DVAA" followed by U+0332, U+0335 COMBINING SHORT STROKE OVERLAY, U+0338 COMBINING LONG SOLIDUS OVERLAY or U+20DD COMBINING ENCLOSING CIRCLE, which NFKC leaves apart from the A, names DVAA. A mark counts as directly after "DVAA" only where it is written as itself, not as a character reference, directly after a letter or another mark, and a mark that does not is kept apart from the name, so that NFKC in the third step below does not join it to the last A: `DV**AA**` followed by U+0301, `DVAA&#x301;`, `DV**AA**&#x301;` and `DV**AA&#x301;**` name DVAA, while NFKC alone gives "DVA" followed by U+00C1. First, going along the line, its HTML is removed wherever it stands, also where it starts inside a link destination or title and ends after the `)` that closes them: each comment, processing instruction, CDATA section and declaration from its opening `<!--`, `<?`, `<![CDATA[` or `<!` and an ASCII letter to the first `-->`, `?>`, `]]>` or `>` after it, respectively, or to the end of the line when none follows, and each tag from `<` or `</` and a name, which is an ASCII letter followed by any ASCII letters, digits and hyphens, to a `>` right after the name or, after `/` or a character Unicode lists as white space (such as U+00A0 NO-BREAK SPACE), to the first `>` after that if no `<` comes first. Where white space other than a space or tab follows a tag name, the line is also read with only a space, a tab or `/` ending a tag name, and names DVAA when either reading does. Second, going along what remains, each `]` followed by `(` is removed with the text after it to the first `)` if no further `(` comes first, and each `]` followed by `[` with the text after it to the first `]` if no further `[` comes first, whether or not they make a link, then each `!` directly before a `[`, and then the Markdown characters `*`, `_`, `~`, `` ` ``, `\`, `[` and `]`. Third, its character references are decoded, each to the characters it stands for less any such character, so `&#8203;` (U+200B) leaves nothing, and it is brought to Unicode NFKC with each character that Unicode lists as confusable with A, D or V, such as U+0410 CYRILLIC CAPITAL LETTER A, read as that letter. So the name written as `DV&#8203;AA`, `**DV**AA`, `DV<!-- -->AA`, `<b>DV</b>AA`, `[DV](url)AA`, `DV![](x.png)AA`, `[DV](url "<b` U+00A0 `x=")AA>` or in fullwidth letters does not take the line out of the check, while `DV!AA` does not name DVAA. On a line that carries one of the characters above, a combining mark after "DVAA" does not keep the line from naming DVAA, so "DVAA" followed by U+200B and U+0301 names DVAA and the line fails on U+200B. A line of README.md or those pages that states one of the `matrix.json` counts once such characters are removed fails the same way, and each failure gives the line and column of the character.

The HackMyAgent and OASB figures are pinned in [`related-projects.json`](../related-projects.json) too, with the HackMyAgent release they were read from. The check reads "N static checks", "N payloads" and "N attack payloads" against the pinned HackMyAgent figures and "N controls" and "N domains" against the pinned OASB figures, on every line of README.md and those pages in that letter case, and fails when one states a different number.
