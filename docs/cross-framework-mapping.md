# Cross-framework mapping

## Cross-Framework Mapping

This matrix maps every technique to four external references:

| Framework | What It Provides |
|-----------|-----------------|
| [HackMyAgent](https://github.com/opena2a-org/hackmyagent) | Automated detection (318 static checks, 164 attack payloads) |
| [DVAA](https://github.com/opena2a-org/damn-vulnerable-ai-agent) | Lab validation (21 agents: 16 deliberately vulnerable, 1 hardened reference, 4 control-protected variants; 12 vulnerability categories) |
| [OASB](https://oasb.ai) | Defensive controls (46 controls across 10 domains) |
| MITRE ATT&CK / ATLAS / OWASP LLM | An index of which techniques this repository's mapping documents name against each framework, and which they do not |

See [cross-references/](../cross-references/) for detailed mapping documents. The DVAA figures are pinned in [`related-projects.json`](../related-projects.json) with the DVAA release they were read from. On each line naming DVAA in README.md and in the pages that took its reference text (`PAGES` in the script, this page among them), `python3 scripts/check_readme_claims.py` reads the wordings "N agents", "N deliberately vulnerable", "N hardened reference", "N control-protected variant(s)", "N vulnerable agent(s)" and "N categories" (up to two words, each a run of ASCII letters and hyphens, may stand between the number and "categories"), in any letter case with one space between words, and fails when one states a different number. A DVAA figure worded any other way is not checked. A line naming DVAA fails the check when it carries a format character (Unicode category Cf, such as a soft hyphen or a zero width space), a control character other than a tab, a Hangul filler, a combining mark that Unicode lists as default ignorable, such as a variation selector, or a code point that Unicode lists as default ignorable without assigning it, because such a character can keep a figure from being read while the line still shows it. A line names DVAA when it contains "DVAA" once such characters are removed, either as it then stands or after three more steps, with no combining mark (Unicode category M) directly after it that NFKC joins to the last A. So "DVAA" followed by U+0301 COMBINING ACUTE ACCENT, which NFKC joins to the A as U+00C1 LATIN CAPITAL LETTER A WITH ACUTE, does not name DVAA, nor does "DVAA" followed by U+0332 COMBINING LOW LINE and U+0301, while "DVAA" followed by U+0332, U+0335 COMBINING SHORT STROKE OVERLAY, U+0338 COMBINING LONG SOLIDUS OVERLAY or U+20DD COMBINING ENCLOSING CIRCLE, which NFKC leaves apart from the A, names DVAA. A mark counts as directly after "DVAA" only where it is written as itself, not as a character reference, directly after a letter or another mark, and a mark that does not is kept apart from the name, so that NFKC in the third step below does not join it to the last A: `DV**AA**` followed by U+0301, `DVAA&#x301;`, `DV**AA**&#x301;` and `DV**AA&#x301;**` name DVAA, while NFKC alone gives "DVA" followed by U+00C1. First, going along the line, its HTML is removed wherever it stands, also where it starts inside a link destination or title and ends after the `)` that closes them: each comment, processing instruction, CDATA section and declaration from its opening `<!--`, `<?`, `<![CDATA[` or `<!` and an ASCII letter to the first `-->`, `?>`, `]]>` or `>` after it, respectively, or to the end of the line when none follows, and each tag from `<` or `</` and a name, which is an ASCII letter followed by any ASCII letters, digits and hyphens, to a `>` right after the name or, after `/` or a character Unicode lists as white space (such as U+00A0 NO-BREAK SPACE), to the first `>` after that if no `<` comes first. Where white space other than a space or tab follows a tag name, the line is also read with only a space, a tab or `/` ending a tag name. Where a character other than an ASCII letter, digit, hyphen, white space, `/` or `>` follows a tag name, such as `\` or `<`, the line is also read as a browser reads a tag in an HTML block, with a name that is an ASCII letter followed by any characters other than white space, `/` and `>`, so `DV<x\>AA` and `D<D\\</b>VAA` name DVAA. Where `/` or white space follows a tag name and a `"` or `'` follows that before any `<` or `>`, the line is also read with each quote in a tag after that `/` or white space passed over whole with the text up to the next such quote on the line, as an attribute value in quotes, which CommonMark and a browser read past any `<` or `>` it holds: a tag then runs to the first `>` that stands in no such value if no `<` that stands in none comes first, so `DV<b x="<">AA` and `DV<b title='>'>AA` name DVAA. A quote that no such quote follows on the line is read there as any other character. The line names DVAA when any reading does. On the way, as CommonMark reads them, the character a backslash escapes (an ASCII punctuation character directly after it) and the text of a code span are kept as text, which no later step reads as markup, HTML, a link span or a character reference; the backslash and the backticks around the code span are removed, and a backslash before any other character stays. A run of backticks opens a code span that the next run of as many backticks on the line closes, and the text between them loses one space at each end when it starts and ends with a space and holds another character. So `DV\*AA` and `` `DV*AA` `` read "DV*AA" and do not name DVAA, as `DV&#42;AA` does not, while `` ` DV `AA `` names DVAA. Going along the line, no code span is read from the first place where a backtick after it could be read another way: a code span whose text holds a `|` (another table cell), a `<` or a `&` (read by a browser in an HTML block); a `<` whose HTML holds a backtick or quote or has no close, or, where it starts no HTML, with no `>` after it or a backtick or quote before the first `>`; and a `]` followed by `(` or `[` with no `)` or `]` after it before a further `(` or `[`, or with a backtick, quote, backslash or `<` before it. No code span is read on a line that carries one of the characters above, nor on the lines after a line where, read with no link label removed as below, code spans are not read or stop being read or a run of backticks finds no closing run, up to a blank line. Going along the line, where a `]` that no backslash escapes and that stands in no code span or HTML is directly followed by a link label (the `[` and the text after it to the first `]` that no backslash escapes, with no `[` that no backslash escapes before that `]`, as CommonMark bounds a label though of any length), the `]` is removed with the label when the label is blank (empty or of white space only) or one that the page holding the line defines, and no HTML, escape or code span starts inside the label; otherwise the `]` stays, and the `[` and what follows it are read on. A page defines a label where, once such characters are removed, it holds a `[` that no backslash escapes followed by that label, a `]` and a colon, two labels being the same when they are after Unicode case folding, with white space at either end removed and each run of white space inside read as one space. Where a `]` is so directly followed by a `[`, the line is also read with no label removed, and it names DVAA when any of its readings does. So `[x][DV](url)AA`, which CommonMark shows as "[x]DVAA" where the page does not define the label `DV`, names DVAA, while `[DV][dvaa]AA` names DVAA only where the page defines the label `dvaa`. Second, going along what remains, each `]` followed by `(` is removed with the text after it to the first `)` if no further `(` comes first, whether or not they make a link, then each `!` directly before a `[`, and then the Markdown characters `*`, `_`, `~`, `` ` ``, `[` and `]`. Third, its character references are decoded, each to the characters it stands for less any such character, so `&#8203;` (U+200B) leaves nothing, and it is brought to Unicode NFKC with each character that Unicode lists as confusable with A, D or V, such as U+0410 CYRILLIC CAPITAL LETTER A, read as that letter. So the name written as `DV&#8203;AA`, `**DV**AA`, `DV<!-- -->AA`, `<b>DV</b>AA`, `[DV](url)AA`, `DV![](x.png)AA`, `[DV](url "<b` U+00A0 `x=")AA>` or in fullwidth letters does not take the line out of the check, while `DV!AA` does not name DVAA. On a line that carries one of the characters above, a combining mark after "DVAA" does not keep the line from naming DVAA, so "DVAA" followed by U+200B and U+0301 names DVAA and the line fails on U+200B. A line of README.md or those pages that states one of the `matrix.json` counts once such characters are removed fails the same way, and each failure gives the line and column of the character.

The HackMyAgent and OASB figures are pinned in [`related-projects.json`](../related-projects.json) too, with the HackMyAgent release they were read from. The check reads "N static checks", "N payloads" and "N attack payloads" against the pinned HackMyAgent figures and "N controls" and "N domains" against the pinned OASB figures, on every line of README.md and those pages in that letter case, and fails when one states a different number. The title of each OASB-1 control is pinned there from the same release, under `oasb.controlTitles`: the Mitigation section of each technique page lists the controls `matrix.json` maps to the technique with their titles, and `python3 scripts/check_technique_pages.py` fails when a section differs from that rendering or when `matrix.json` maps a control with no pinned title.
